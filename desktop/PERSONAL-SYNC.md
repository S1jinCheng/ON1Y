# 个人 Win / Mac 同步

如果希望通过 iCloud 同步书架、Paper 和 PDF/电子书，可使用新增的[资料库文件夹同步](ICLOUD-SYNC.md)。下文描述服务地址方式的同步范围；两种方式不能同时开启。

这是可选的单人、单资料库同步功能，不提供云端注册或多用户管理。每个桌面数据库只能绑定一个本地账号。两端账号名称、密码、数字 ID 可以不同，配对依据是同一个服务地址和配对密钥。

默认关闭。仅在用户保存并开启后，应用运行期间每 30 秒尝试同步，也可以手动同步。关闭应用后不在操作系统后台继续运行。服务暂时离线不影响本地阅读和编辑。

## 范围

- 同步订阅/收藏内容的标题、正文、AI 摘要、笔记、批注 HTML、收藏、已读、重要程度、标签、主题归属以及自定义主题。
- 删除同步为墓碑，其他设备进入回收站，不远程执行不可恢复的物理删除。恢复也会同步。永久删除后的设备不会自动重新创建该条目，除非收到显式恢复。
- 不同步 Cookie、密码、API Key、代理、本地文件路径、订阅抓取配置、任务队列、热榜、书架、论文库、PDF/电子书、内容关系和其他未列出的元数据。
- 不改变原有订阅抓取开关。建议只在一台设备开启自动抓取及 AI 处理，避免重复请求和计费。
- 精确 URL 相同的文章按同一条内容合并，主题按 slug 合并；带不同参数的 URL 不会自动归一化。

## 使用入口

两端使用包含此功能的新构建，进入设置 → 账号 → 数据 → 跨设备同步。

1. 首次使用建议在两端各导出一次账户备份。
2. Windows 填入服务地址与配对密钥，开启并保存，然后立即同步。
3. Mac 登录自己的本地账号，填写相同服务地址和密钥，开启同步。
4. 首次连接合并现有数据，不清空本地资料。不同字段的编辑自动合并，同字段冲突保留双方副本，在界面中逐项确认。
5. 修改设置后需要先保存，再手动同步。留空密钥输入框会保留原密钥；接口不会返回密钥。

大资料库按批次传输，每轮最多上传 50 个操作，可能需要多轮。已排队数量不包括下一轮尚未扫描的本地变化。最后成功同步表示最近一轮成功，不保证没有尚待扫描的变化。

## 暂不部署 VPS 的本机验证

同步仍需要一个双方能够访问的中转服务。可以先只在本机测试；也可以由一台电脑临时运行，另一台通过 SSH 隧道连接。两端直接互通时，运行服务的电脑需要保持在线。以后迁到 VPS 不需要改变同步协议。

服务与桌面 API 分离，**不要把桌面 8765 端口直接暴露到公网**。

在仓库根目录、独立 Python 3.11+ 虚拟环境中安装轻量依赖即可，不需要 Paddle/OCR：

```sh
python -m pip install -r packaging/device-sync-requirements.txt
```

生成随机密钥，复制后妥善保存，勿提交到 Git：

```sh
python -c "import secrets; print(secrets.token_urlsafe(32))"
```

macOS/Linux 启动示例：

```sh
export ON1Y_DEVICE_SYNC_KEY='替换成刚才生成的随机密钥'
python -m on1y.device_sync.server --db ./data/personal-sync/relay.sqlite3
```

Windows PowerShell 启动示例：

```powershell
$env:ON1Y_DEVICE_SYNC_KEY = '替换成刚才生成的随机密钥'
python -m on1y.device_sync.server --db ./data/personal-sync/relay.sqlite3
```

默认监听 `127.0.0.1:8787`，本机界面填写 `http://127.0.0.1:8787`。远程连接必须使用 HTTPS，或先建立 SSH 隧道再连接本机地址。例如服务运行在已经启用 SSH 的 Windows 电脑时，可以在 Mac 建立：

```sh
ssh -N -L 8787:127.0.0.1:8787 username@windows-host
```

这不是自动网络发现，也不会替你开启远程登录、防火墙或部署服务。VPS、域名、TLS 配置留待实际部署时完成。

## 数据与安全

- 密钥等同于整个资料库的访问权，仅限自己的可信设备。第一版没有单设备撤销，撤销访问需轮换服务密钥并更新保留设备。
- 非本机 HTTP 被拒绝；不跟随重定向，不使用系统代理环境变量传输密钥。
- 服务端能读取文章和笔记，**不是端到端加密**。SQLite 与本地配对密钥依赖操作系统文件权限和磁盘加密保护。
- 服务会保留变更日志、墓碑及冲突历史，第一版不自动清理。删除内容不等于从所有服务备份中永久擦除。
- 服务端资料库 ID 和同步游标校验值会固定到设备。服务被替换或历史回滚时停止同步，避免错库合并。不要删除本地同步表或重建服务数据库来修复报错。
- 改服务器地址仅用于迁移同一份完整服务数据库，不支持直接切换到另一个资料库。
- 备份桌面完整数据库和中转数据库。运行中的 SQLite 使用 SQLite backup API 或停服务后备份，不要只复制主文件而遗漏 WAL。

## 实现与验证

`on1y/device_sync/` 包含协议、独立中转服务、本地数据映射、同步引擎及桌面 API。新增 `device_sync_*` 表是独立、增量创建的，不重建原有业务表。

本地数据库保存业务变化；每轮在 SQLite 事务里读取一致快照，与已确认的远端基线比较，生成持久化 outbox。它记录净变化，不是每次按键或历史操作的审计日志。单条操作暂限制为 4 MiB。

服务端按字段基线版本合并，标签按成员分别处理。冲突默认保留服务端值，同时保存提交版本，用户可以采用提交版本或手动合并。旧冲突之后若同一字段又被修改，禁止用旧提交版本直接覆盖。

本地应用远端内容、更新索引、保存冲突、确认 outbox 和推进游标都在同一事务里完成。网络重试使用相同操作 ID；网络请求期间产生的新编辑通过三方比较保留。同步运行时不持有覆盖整个网络请求的数据库写锁。

测试用两份独立 SQLite 数据库模拟 Windows / Mac，通过真实 FastAPI 路由往返，不连接个人服务或上传真实资料：

```sh
python -m pytest -q tests/test_device_sync.py
npm --prefix frontend test
```

第一版扫描本地同步范围生成差异，适合个人资料库；暂不做大规模增量索引优化、二进制附件、端到端加密、多进程桌面同步或多用户托管。
